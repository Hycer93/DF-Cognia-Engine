# 阶段1 落地：raw 叶子边（摘要 ↔ 原文 垂直打通）

> 执行日期：2026-11-24
> 台账号：#50（独立于 #49 跨簇管道，见台账）
> 性质：**前置依赖补丁**，只解决【摘要 ↔ 原文】垂直打通；**不解决跨簇、不解决自动组装**

## 一、背景：为什么要这一刀

用户连问三层，逐层暴露系统缺陷：

1. **"走记忆系统查我的信息"** → 只能裸 SQL 捞散点
2. **"冷启动查呢"** → 查不出"我叫什么"，因为摘要层无署名
3. **"专利文档上没有么"** → 名字在 `raw_corpus` 原文层（38/50 条写明"发明人 黄艺超"），
   但摘要层 `core_memory_card` 精炼时把署名砍了

**根因**：系统有"摘要层"和"原文层"两套数据，但**两层之间零连接键**——
摘要卡 `source_ref=corpus2_...#S7-02`，原文 `source_ref=文件迁移:.../xxx.txt`，格式完全对不上。
F30/F40 的图里只有摘要卡，**原文层根本不在图里**。

**结论**：用户信息、技术方案细节都在原文层，但系统没有一条"从摘要下钻到原文"的路。

## 二、这一刀做了什么

把 `raw_corpus`（原文层）作为**叶子节点**挂进 F30/F40 的图，用**标题 2-gram Jaccard** 建边：

```
摘要卡 (core_memory_card) --raw:doc(jaccard≥0.4)--> 原文节点 (raw_corpus)  ←叶子, 不再扩散
```

### 关键设计（对应四条硬约束）

| 约束 | 实现 | 位置 |
|---|---|---|
| **raw 只做叶子不扩散** | `_edges_from` 一进来 `is_raw_node(iid)` 直接返回 `[]` | `future_sim_minloop.py` |
| **固定标题 2-gram Jaccard，阈值 0.4 可配** | `_raw_bridge()` + `_clean_title()`；`CONFIG.raw_bridge_jaccard` | 同上 |
| **明确标注不解决跨簇/组装** | 模块头 + CONFIG 注释 + 本文件 | 多处 |
| **F40 保持摘要层最短路径语义** | F40 反向 BFS 跳过 `raw:` 边（原文不可能是锚） | `f40_backward` |

### 为什么是"标题级"而不是"全文级"（原型已踩的坑）

第一次原型用"卡全文 vs 原文前 300 字"做 2-gram，**重合 41 分却匹配到错的那篇**——
因为专利全文术语高度雷同（都写"本发明""神经网络""权利要求"），**全文相似度分不清谁是谁**。
改成标题对标题 + 标题清洗（剥 `Pxx专利：`前缀、括号注记）后：
- P24：0.73 → **0.97**
- P28：0.40（压线）→ **0.68**（稳定）

## 五、已知观测点（数据债，非本补丁问题）

1. **原文层自身有 id/内容错位**：`patent.多认知头协同神经网络推理` 这篇 title 是多认知头，
   但 body 实际是"ODL 域外联动"内容。这是**原文入库时的数据债**，不是桥接问题。
   影响：部分卡 raw_drill 抽不到署名（因为正文确实不带署名段）。
2. **覆盖率 37%（35/95）**：专利簇 95 张卡里只有 35 张能桥到原文。原因：
   ①部分卡是"入库行为卡"「专利矩阵同步入库…」本身不是专利本体；
   ②原文层只 49 篇，部分卡对应原文未入库。**这是数据缺口，不是算法问题**。
3. **raw 边权重低于 relation**：F20 下 raw 边 ≈0.39，relation 边 ≈1.43。所以 F30 主路径
   优先走 relation，**只有孤立卡才纯靠 raw 下钻**。这符合"原文是补充细节、不主导演化主线"的定位；
   "直接看某卡原文"请用 `raw_drill()` 出口，而非依赖 F30 主路径。
