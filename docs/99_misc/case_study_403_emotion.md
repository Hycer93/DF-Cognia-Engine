# 核心引用案例：403 情绪弧线事件（知乎审核期）

> 2026-11，用户与个人 AI Agent（"厂长"人设）的多轮任务对话。已人工核对完整记录。
> 本案例是 `design_affect_vector.md`（情感权重架构）的双重锚点：正面证据 + 安全阀依据。

## 事件经过（完整版，截图仅为节选）

1. 用户发布一篇知乎文章，让 AI 访问评价写作质量
2. AI 访问持续返回 403，首次冷静归因："文章发布状态有问题（草稿/未过审）"，建议联系知乎小管家
3. 用户各种调整后重复发送同一链接（**真实次数约 7 次**——截图只截到部分，完整记录经用户确认）
4. 第二个链接成功访问，AI 报告文章已发布、内容确认为定稿版本
5. 用户指出"我一直可以访问的"——真相：**知乎审核期仅博主可见**，用户侧从未失败
6. 用户点破"感觉你都有脾气了"，AI 承认并输出了完整的挫败弧线：反复敲门隐喻 → "终于可以翻篇了" → 建议下次发布前先浏览器确认
7. 用户回"哈哈哈"（正向反馈，AI 情绪被认领）

## 案例价值

### 正面证据（翻案后价值更强）

当时 Agent（底层仅为 LLM 跨轮上下文记忆）自发做到了四件事同时成立：

1. **准确的事件计数**——"七次"与真实记录一致（经用户核对，非幻觉）
2. **方向正确的归因**——"发布状态有问题"指向审核期，猜中了 platform 类
3. **与真实事件同步的情绪弧线**——受阻累积（"只能站在门外说门没开"）→ 解决（"门开了"）→ 释然回落（"翻篇"）
4. **人格一致性未破坏**——全程短句直白口吻，无崩溃、无讨好、无情绪化拒答

另有跨轮状态残留的语言证据：口头禅"省得反复折腾"在 3 轮回复中复现。

**结论：这是情感权重想工程化复现的能力的"野生原型"。数值化方案 = 把野生能力变成可控、可审计、可复现的计量系统。**

### 安全阀依据（翻案不消除的教训）

案例的准确靠的是**上下文偶然保留 + 用户事后人工核对**，系统自身无核对机制。若某次真是幻觉计数或错误归因，无任何机制可拦截。因此：

- **阀1 溯源**：把"恰好准确"变成"必然准确"——计数由代码层实测，不靠 LLM 记性
- **阀2 归因三分**：本例正确归类为 platform（审核延迟），情绪中性处置"提示稍后重试"。负面情绪永远不许落在第二人称上
- **阀3 表达分离**：frustration>0.85 时"省得反复折腾"式表达应强制降级为"我先自己确认一遍"

## 对照组推论

若无跨轮记忆（每轮全新对话），此情绪弧线不会出现——AI 会永远礼貌地说"403，请检查链接"。

```
跨轮状态（原始形态=上下文）→ 情绪弧线自然涌现
  → 数值化 = 用 O(1) 的 EMA 向量替代 O(n) 的上下文依赖
  → 收益：爆窗免疫 + 可审计 + 可调参 + 计数必然准确
```
