# 复现率门禁 v0.1（设计冻结）

> 状态：**用户终裁冻结**（2026-11-08）。
> 血统：专利五（异常驱动维度衍生）× 专利一（可复现性判定）焊接件；DS 二轮评审（2026-11-08）规格化贡献。
> 定位：异常认知样本的价值裁定自动化——变异猫（新知识）与残缺猫（噪声）的分流器。
> 实施排期：Week2；上线后运行三个月采集日志重标参数，日志即专利从属权利要求实施例素材。

## 一、设计原则（四条铁律，全部来自终裁共识）

| # | 原则 | 出处 |
|---|---|---|
| 1 | 判定权显式排除模型隐空间打分——不可审计即不采用 | DS 评审·分歧6 |
| 2 | 网络固定，生长在上层——门禁是编码树的事，不是神经元的事 | DS 评审·分歧1 |
| 3 | 与专利一焊接：可复现性管入库，复现率管转正 | 会话首创·DS 规格化 |
| 4 | 逐层流转语义（观察→转正/消亡），不做软门混合 | DS 评审·分歧5 |

## 二、核心机制：三状态 + 两条流转

```
新异常样本（四档判定 new 且无法挂既有编码）
        │
        ▼
┌─────────────────┐
│ on_watch 观察队列  │  watchlist_pool.jsonl
│                  │── 复现判据达标 ──→ 【promoted】新建 DFCP 编码挂树
│                  │    （查重熔断失败→退回 on_watch，记录原因）     │
│                  │
│                  │── 滑动窗口 T=30 天无新增有效命中 ──→ 【dead】
│                  │    （永久留档，不删；可复活，规则见 §5）        │
└─────────────────┘
```

三状态：`on_watch` → `promoted`（进主库+编码树）/ `dead`（归档可复活）。

## 三、复现计量口径（终裁 A 案：检索命中驱动唯一主计量）

**复现的定义**：跨会话的检索命中事件——不同会话中 ≥2 个**不同 inst_id 源头**的查询，以 match_eff 达标命中**同一 on_watch 锚**，且通过语义残差校验（命中查询彼此相似 <0.7，防同题复读；递进追问、同主题分支推演豁免——口径同护栏⑥）。

**计量细则（终裁补充）**：
- 只有 ask() 产生、落入 cited_log、命中 on_watch 锚、通过语义残差校验的命中，才累加 recurrence_count
- atomic_store 的写入行为**不给**复现计数器加分
- 人工 add、批量导入、corpus 教材样本，一律不计入复现
- 理由：度量的是"这条认知能否在不同独立问题里反复被**需要**"，不是"被反复**写进**"——写入侧可人工灌入伪造信号；无人检索命中的异常主题对智能无持续价值，不转正符合目标
- **补偿兜底**：admin_promote 人工转正特权通道——不走自动门禁、强制留审计日志，不污染自动统计

## 四、转正判据（双层门控）

```
主判据（复现统计，全满足）：
  recurrence_count ≥ K=3            跨会话独立命中次数
  AND session_spread ≥ 2            至少 2 个不同会话（防单会话刷量）
  AND semantic_residual_check       命中查询彼此相似 < 0.7（防复读）

熔断条件（防维度爆炸，簇键护栏血统）：
  新编码候选 vs 既有编码树查重，结构距离 < 阈值 → 拒绝转正
  退回 on_watch，不销毁、不转正、不合并，记录原因，
  可在编码树后续迭代后再次尝试转正
  （L_smoothness→树演化约束：新码挂树不得与邻居节点语义跳跃）
```

**消亡计时**：T=30 天为**滑动窗口**——连续无新增有效命中的时长，非进入观察起的绝对时间；每次有效命中刷新倒计时。

## 五、复活规则（终裁：清零重来，历史封存）

- dead 条目永久保留完整档案：原始命中列表、旧 recurrence_count、消亡时间、消亡原因——审计与溯源用
- 新同源异常匹配到 dead 锚：状态 dead → on_watch，**recurrence_count 从零重新累计**
- 历史计数封存至独立字段 `legacy_recurrence`——只供查阅/绘图/长期趋势统计，**不参与转正判据**
- 语义：想法再次被抛出，需重新证明当下是稳定模式；过去火过只是参考，不能透支当年热度
- 防的漏洞：远古昙花一现凑够 K 后沉寂、数月后偶现一次即瞬间转正——违背"稳定持续可复现"本意
- **例外特权**：admin_revive 人工复活可**选择**是否继承历史计数，强制留日志，属人工裁定

## 六、管道挂点（三处，零新依赖）

| 挂点 | 现有件 | 门禁动作 |
|---|---|---|
| ① 入库分流 | atomic_store | 四档判定 new 且需建新码 → 不直接落树，进 watchlist_pool |
| ② 检索计量 | ask() / cited_log | 每次有效命中 on_watch 锁 → recurrence+1、记 session_id（cited_log 加 watch_hit 字段） |
| ③ 转正执行 | promote()（新函数） | 判据达标 → 建码挂树 → 写 code_changelog（护栏②）→ 标 promoted + derived_from 指向触发命中列表 |

## 七、与 X1-X8 的合并（语义区分，统一计量）

| 机制 | 固化对象 | 目标编码位 |
|---|---|---|
| 复现率门禁 | 异常**主题**（知识维度） | domain / scene 场景编码 |
| X1-X8（迁入后） | 反复出现的推理**模式** | behavior 行为编码 |

两套共用同一计量基础设施（watchlist_pool + 复现统计），保持产出编码位区分。

## 八、参数表（全部 [先验-可校准]，运行三个月重标）

| 参数 | 初值 | 依据 |
|---|---|---|
| K 复现次数 | 3 | X1-X8 固化门槛沿用 |
| T 消亡窗口（滑动） | 30 天 | 月度整理周期对齐 |
| session_spread | 2 | 反刷量下限 |
| 语义残差阈值 | 0.7 | char2gram 同题复读实测（equivalent 线 0.78 附近）；换基座全量重标 |
