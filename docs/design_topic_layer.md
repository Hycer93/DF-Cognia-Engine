# Topic 抽象锚层设计（DFCP × Memora 融合，v1.0 终审版）

> 状态：**用户终审通过（2026-11-13），待开发**
> 来源：用户方案（融合微软 Memora 2026 三层范式）+ 主 AI 四点审读 + 用户终裁定见（四点全裁 + 两条补充隐患）
> 定位：在现有全量治理基建**顶层**新增一层粗粒度降噪索引，不动任何底层事实判定。

## 一、核心定位（一句话）

**Memora 管"宏观主题不散"，DFCP 管"微观每条可审"。**

Topic 层 = 粗粒度降噪索引。它不是用来替代 entity、不是替代三级级联冲突判定、不参与置信度计算、不修改演化链标记。

## 二、四层堆叠架构

```
┌─────────────────────────────────────────────┐
│ L4 TopicAbstraction 主题锚（新增·纯增量）      │  主题收敛 / 聚类导航 / 全局去碎片
│     topic_id, topic_abstract, topic_vector,  │
│     cue_anchors, create_ts, update_ts        │
├─────────────────────────────────────────────┤
│ L3 Entity 谱系层（已有，不动）                 │  同本体合并 / 重编号对齐 / 演化链挂载
├─────────────────────────────────────────────┤
│ L2 认知原子层（已有核心，不动）                │  单条记忆独立生命周期
│     独立置信升降 / 冲突 / 分类 / 作废 / 归档   │
├─────────────────────────────────────────────┤
│ L1 三粒度内容层（已有，不动）                  │
│     summary（检索向量）/ detail（复核下钻）    │
│     / source_ref（原文溯源）                  │
└─────────────────────────────────────────────┘
```

与 Memora 的本质区别（写死，防后面写代码时混淆）：
- **Memora 三层是"一个主题=一条全局唯一抽象，内部持续追加"**——容器范式，无法细粒度治理、无法单独作废旧结论、无 scar_case / 策略演进分层
- **DFCP 四层是"同一条原子的多粒度拆分 + 顶层独立索引"**——每条原子独立可审可证伪可消亡，Topic 只是路由

## 三、六条固化规约（开发时逐条对照，不可绕过）

### 规约 1：topic 与 entity 是两套粒度，不可互相替代 ⚠️文档级红线

| | entity | topic |
|---|---|---|
| 本质 | 本体（是谁） | 议题（谈什么） |
| 例 | P10、P22 是**不同实体** | P10、P22 **可属同一主题簇** |
| 操作 | 合并/重编号/演化链 | 只做检索路由与冲突拦截 |

**禁止任何"用 topic 取代 entity"的实现**。两者多对多共存，互不修改。

### 规约 2：检索 = 并行多路召回取并集，禁止串行漏斗 ⚠️核心红线

❌ 错误范式（串行漏斗，第一层跑偏即静默丢失召回）：
```
query → 匹配主题锚 → 只在主题内检索
```
✅ 正确范式（并行多路 + 并集 + 后置过滤）：
```
query → ┬─ topic 锚匹配 top-2 → 各主题子集召回 k 条
        ├─ 全库直查兜底召回 1-2 条
        └─ 两路并集 → 排序 / 去重 / sim 过滤
```
**价值定位摆正：它是降噪索引，不是加速神器。** 核心收益是减少无关记忆进入冲突比对候选池、E8 影子测试候选池，降低假阳性（张冠李戴率）。

### 规约 3：topic 归一 = judge 管道裁定 + hold 待归池，禁止当场强制二选一

- 新原子挂靠判定复用现有 **judge 四档**（store/hold/discard/conflict_suspect）
- 拿不准 → 挂 `topic_id=null` 进**待归主题池**，交夜间批量复审（E7）
- **禁止当场"新建锚 vs 挂旧锚"二选一强制裁决**——两种退化（簇越拆越碎 / 硬塞不相关）都源于此
- LLM 判定"是否同一主题"天然主观，保守路线：宁缺毋滥，与全系统风格一致

### 规约 4：冲突拦截单向（粗→细），同 topic 必走全级联 ⚠️上线前必须进回归用例

粒度顺序：**topic（粗）→ entity（中）→ summary/detail/source_ref 级联（细）**

拦截规则（只单向）：
- ✅ **topic 不同** → 跳过冲突比对（前置拦截，砍掉"句式相似但无关"误报）
- ✅ **topic 相同** → **无论 entity 是否一致，一律走完整冲突判定流水线**（含演化链例外）

❌ 致命错误写法：`同 topic 就跳过冲突`——一旦写反，P10/P12/P22 演化冲突全部消失在视野里，整个冲突治理体系报废。

**上线前回归用例必须包含**：同 topic 不同 entity 的演化对（P10→P22 口径）、同 topic 同 entity 的版本迭代对，断言全部进冲突队列。

### 规约 5：topic 不参与底层事实判定

Topic 只控制两件事：
1. 检索候选池范围
2. 冲突比对是否进入

**禁止**：topic 权重掺进相似分、掺进置信度计算、修改 entity、修改演化链标记。底层事实判定仍归原体系（memory_relations 三级级联 + confidence_dynamics）。违反则因果链污染，排查成本指数级上升。

### 规约 6：主题锚自身有生命周期（用户补充隐患①）

锚不是建完就对的——随着新记忆灌入，旧抽象会过时（锚本身失效=失效索引）。

E7 夜间管线新增两条：
- **高活跃主题**：周期性重提炼 topic_abstract + 重向量化 topic_vector（refresh，不换 topic_id）
- **长期低访问/少挂载主题**：标记 `archived`（不删除，保留索引历史，检索时降权）

## 四、落地改动清单（极小侵入、纯增量）

| 项 | 内容 | 触碰文件 |
|---|---|---|
| 新表 | `topic_abstraction`（topic_id/topic_abstract/topic_vector/cue_anchors/create_ts/update_ts/status） | corpus_store.py 加 schema |
| 原子挂载 | `memory_hook.add` 管道加一步 topic 归一（judge 四档裁定，见规约3） | memory_hook.py |
| 检索路由 | 多路并行召回（见规约2） | cgraph/memory.py `_query` + memory_hook query 路径 |
| 冲突前置 | topic 不同→跳过；相同→全级联（见规约4） | memory_relations.py `classify_and_link` 入口（现有 entity/占位过滤器**之前**新增 topic 过滤器，顺序：topic → entity → 占位 → 级联） |
| 存量回填 | **只建高置信锚**（P10/P12/P22、非农复盘、脑区映射等已知同源簇），其余 `topic_id=null` 等夜间收敛——与 memory_class 回填范式对齐（用户定见：一次性全量 LLM 聚类易批量错分且难回滚；分散夜间增量可观测、可分批关停、可回看日志） | 一次性脚本 + E7 |
| cue_anchors | 复用现有别名体系（memory_alias.py） | 不新增机制 |
| E7 新管线 | 主题锚 refresh + 归档 + hold 池复审 | scripts/nightly_run.py 挂载 |

**治理层零改动**：memory_relations 三级级联 / confidence_dynamics / 复现率门禁 / E1-E5 / 五分类——一行不动。

## 五、上线策略（白名单 + A/B 对照）

1. **先开白名单**：只对一部分记忆开启 topic 路由（开关：config 或环境变量），保留一键关闭
2. **A/B 对照指标**：
   - 冲突队列假阳性率（晨报误报数）
   - E8 影子测试 miss 率 / 张冠李戴率
   - 检索召回命中率（同题 top-k 相关度）
3. 指标无改善或恶化 → 关开关回滚，锚数据保留不删
4. 验证通过后逐步放量

## 六、验收标准（开发完成的判定）

- [ ] 回归用例：同 topic 不同 entity 演化对（P10→P22 口径）→ 断言进冲突队列
- [ ] 回归用例：同 topic 同 entity 版本迭代对 → 断言进冲突队列
- [ ] 回归用例：topic 不同 → 断言跳过比对 + 落审计日志（不静默）
- [ ] 回归用例：串行漏斗禁用——锚匹配错误时全库兜底仍可召回正确原子
- [ ] hold 池：拿不准的原子挂 null 不强制归一，E7 可复审
- [ ] A/B 报告：冲突假阳性 / E8 张冠李戴率有可观测下降
- [ ] topic 权重未出现在任何相似分/置信计算中（代码审查断言）
