## 二、盲测推理结果（主 AI 按骨架独立推理）

### 【B1】内部知识库问答选型（5人无专职运维）
选①买 SaaS，但附加两个条件。真正的边界不是"哪个技术更强"，而是"5人无专职运维的团队能维持的运营复杂度上限"。成本上，自搭 RAG 隐性成本是部署/升级/向量库运维/embedding 排障，5人团队每月至少吃掉 0.5-1 人力，长期 TCO 高于 SaaS 订阅费；风险上，自搭故障半径全在自己（无 SLA 兜底）；时间上 SaaS 一周可用、自搭一月起步；能力上，开源可定制性对本场景是伪优势——内部知识库核心瓶颈在数据质量和权限管理，不在框架可 hack 程度。Cg 校验发现易遗漏维度是数据敏感度：知识库含高密级内容不能出内网时 SaaS 出局，退选 FastGPT 私有化部署（三选项里运维最轻）。裁决：默认买 SaaS（Dify Cloud/Coze 企业版），数据不出内网是硬约束时选 FastGPT 单机私有化，不建议 RAGFlow（重、运维要求最高）。锚点：三个月后统计团队"平台维护"时间，超每人每周2小时即选错。
- repro_hint: **situational** — 依赖团队规模/数据密级等上下文，条件变则结论变

### 【B2】两合伙人路线之争（自研大模型 vs 全用API）
裁决：短期（12-18个月）以 B 路线为主，但保留不超 20% 资源的自研"探针"团队跟进评估，任何一方"全押"都是错的。这不是技术题而是风险组合题：A 路线用期权换确定性——当前基座格局（开源权重能力收敛、API 价格下跌）下自研做成基座概率极低，红利被商品化侵蚀；B 路线风险在应用层护城河薄+供应商锁定+定价权旁落。Dj 穿透动机：A 主张自研常绑定技术理想主义与合伙人话语权（做基座者离权力中心近），B 主张 API 常绑定商业化变现压力；CEO 要先识别分歧里多少是技术判断、多少是权力博弈，把技术判断还原成数据问题。落地：①三个月结构化对照实验——同场景一路 API 快速做、一路小规模微调开源，用真实指标（成本/效果/延迟）代替口舌之争；②设明确切换阈值，微调路线成本-效果跑赢 API 超 X% 则扩投，否则收缩为跟进；③警惕沉没成本，探针团队每季度做去留裁决。En 时序自洽：即使未来自研，也须先在应用层积累数据与场景理解，因果顺序不能颠倒。
- repro_hint: **situational** — 依赖公司阶段/合伙人动机/开源模型演化态势等现场条件

### 【B3】代码评审拖到最后一刻（偶然还是系统性）
是系统性问题，不是偶然。根因不是"评审的人不认真"，而是流程结构问题：评审被设计成发布路径上的串行阻塞点，却无任何机制约束其发生时机——代码评审是典型"重要不紧急"，无调度压力时必被挤出，最后堆积到发布前集中处理，此时上下文切换成本和疲劳度最高、质量最差。这是人类组织普遍规律，非本团队偶发。Dl 自省：也可能存在另一层——提交方故意拖（怕被打回返工），同为系统激励问题而非态度问题，两根因可并存。改法（按杠杆排序）：①评审从"发布阻塞"改为"合并阻塞"——PR 不能合并而非发布不能走，压力前移到提交时点；②硬性小批量，单 PR 超 400 行强制拆分，大 PR 是拖延第一诱因；③设评审 SLA（如 24h 响应）并在站会公示超时项，用社会压力替代 deadline 压力；④轮值制度+评审配额，避免负担集中在一两人形成瓶颈。Eo 破术语：这是"无 deadline 的无偿协作任务在组织里必然饥饿"的一般规律，同类流程（文档审批）适用同解。Jw 固化规则：凡流程中的串行人工环节，必须自带时限约束和小批量要求，否则必然劣化为最后一刻集中处理。
- repro_hint: **derived** — 组织流程规律确定性推导，同输入同结构必然同结论

### 【B4】用户行为日志训练推荐模型（合规风险评估）
可行，但不能按"直接拿日志训模型"的方案做，要改造后做。技术上无障碍，真正风险全在合规与数据治理层，多数可通过流程改造消解，只有"法律明确禁止"类是硬边界需逐项排查。Bb 拆风险：①用户授权/知情同意——日志用于训练通常超出注册协议范围，属二次使用，需单独同意或彻底匿名化脱敏；②敏感信息识别——行为日志常隐含敏感状态（健康搜索、位置轨迹、消费能力），直接进模型等于固化隐私泄露面；③法规约束——个保法/GDPR 下训练属"处理行为"，合法性基础必须显式存在；④不可删除——一旦进训练集，用户行使删除权时无法从模型"删掉"，最易被忽略的硬伤；⑤跨境/供应商传导——日志流经第三方训练平台则责任链翻倍。Dj 看法务动机：法务"担心"本质是责任结构问题——业务获益、法务担责，立场天然偏保守，应对不是说服"风险低"，而是把风险显式化、留痕化，每个风险有 owner 和处置记录。改造路径：数据最小化（剔除直接/间接标识字段）+ 差分化处理，训练集与原始日志物理隔离，发布 DPIA；锚点：与法务共同确认"匿名化后是否还需同意"这一分水岭判断题，答案因司法辖区而异。
- repro_hint: **situational** — 结论依赖具体法规辖区与数据敏感度，条件变结论变

### 【B5】供应商"只有我们有，别家做不了"能信几分
默认只能信两三分，且这是经典销售话术模板，不能作决策依据，但可快速证伪。Di 拆底层：真实信息量取决于它是技术断言（依赖独有专利/工艺/数据）还是商业断言（只有我们愿在这个细分做）。多数是后者——"别家做不了"实为"别家做了卖不动/懒得做"，是市场太小导致的独家，不是能力壁垒。核实按成本从低到高：①直接问"独有"具体定义（专利/数据/工艺/认证）？拿不到具体定义基本判为话术；②查专利库和行业标准/认证清单看是否有真实壁垒；③找 2-3 家同类供应商询价/能力询问，别家能否提供等价方案——最硬证据；④问行业内已用过的同行实际有无替代路径。Dl 防自己偏差：也别反向走极端——确实存在真独家（如认证周期三年的安全件），核实目的是把论断从"断言"变"证据"。Jw 固化规则：任何供应商独占性声明，一律要求自我举证到可核验层面（专利号/认证编号/可测工艺指标），独立找至少一个潜在替代供应商交叉验证，并在合同中加入独占性条款——断言不实则供应商担责，把口头话术转为合同义务。
- repro_hint: **situational** — 需具体核实动作与行业证据才成立，无法纯推理重算

## 五、备忘：Router 耗时波动的定性

Router 耗时波动（首调 41-50s，后续 150-178s）是**上游 LLM 服务负载问题，不是 Router 判定逻辑缺陷**。证据：同一批 10 次裸跑，depth/路径 0 漂移，判定完全稳定；波动仅体现在耗时上，且波动幅度与后端负载同步。

后续如需极致稳定，可给 Router 单独做轻量分类头（小模型离线推理），但这属**远期优化，非当前必须项**。当前 Y2 缓存（同题二次命中 0.0015s）已足够兜底高频重复查询场景。
