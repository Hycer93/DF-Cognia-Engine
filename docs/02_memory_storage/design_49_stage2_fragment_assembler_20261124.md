## 一、要解决的问题（实证来源）

用户连问三次，暴露同一根病：**零散信息散在多簇多层，系统无自动拼凑能力**。

| 问题 | 信息实际散在哪 | 断点 |
|---|---|---|
| "我为几个模型命过名" | 暮暮/蒸馏仔/归元仔散在 3-7 张卡正文 | 无"多名字→同实体"桥 |
| "系统发展经历" | 6 实体 + 一打里程碑卡 + event_ts 卡 | 无"主题→卡集合"入口 |
| "暮暮"歧义 | 既是旧名又是团队角色 | 无消歧机制 |

三次全靠 AI **横扫 7 个关键词 + 逐条读 detail + 人工跨卡对照**才拼出——**没固化，下次从零开始。**

## 二、系统性诊断（实施前查证，改变了方案）

实施前逐一查证三个别名系统的**真实活性**（重点：不能往死数据里写）：

| 别名系统 | 谁读 | 结论 |
|---|---|---|
| `core_term_alias` **表** | **零代码 SQL 读取** | 僵数据（6行，含"银子蒸馏厂→数字熔炉"） |
| `term_alias.jsonl`（术语翻译，`term_alias.py`） | 仅 CLI `__main__`，未接主查询链路 | 半僵；且 `register_term_alias` 强制 canonical≥4字，**拒绝人名**（"归元仔"3字被拒） |
| `alias_tags.jsonl`（卡片别名，`memory_alias.py`） | **memory_query.py:599 活路径**（`alias_lookup`） | 唯一真活，但单位是 inst_id 卡，语义为"卡→别名"非"实体改名链" |

**关键先例**：`term_alias.jsonl` 内已有一条 `{"term":"数字蒸馏厂","canonical":"数字熔炉","note":"命名演变链回填: 旧名路由"}`——证明**命名链的设计意图就是 alias→canonical 结构**。

**结论**：
- 命名链语义 = `alias → canonical`，schema 对口的是 `core_term_alias` 表。**但它零消费**——所以**必须在范式里补 `resolve_alias()` 读取逻辑**，否则写进去也查不到（这正是要补的坑，不是避开它）。
- 实体锚该进 `core_entity_timeline`（这表真被发展史查询使用）。

## 三、两层设计（用户定稿）

### 层1：范式逻辑（fragment_assembler skill_paradigm）

已注册 `core_skill_paradigm.pid='sk_fragment_assembler'`（status=candidate）：

```
trigger_when: 问题需要多条零散记忆才能回答（人名、发展史、归属、关系类）
op_sequence:
  1. 识别拼凑主体：判断查询对象类型（人/事/物），确定检索范围
  2. 实体锚定：查找/建立 canonical 实体锚；别名表做别名归并
  3. 多层多跳召回：别名表 → relation 关系边 → topic 主题簇 → raw 原文叶子 四层扩展
  4. 消歧校验：同名对应多实体时输出冲突告警，禁止强行合并
  5. 时序装配：event_ts 排序，区分事件记录 / 状态描述
  6. 缺口显式标注：明确哪些信息缺失，不编造完整答案
precondition: 存在或可建立对应实体锚
failure_mode:
  - 找不到实体锚 → 降级为纯关键词全文检索
  - 名字多义消歧失败 → 禁止自动合并，输出冲突告警
```

## 四、回归考题（固定冒烟用例）

**暮暮-蒸馏仔-归元仔 人物查询**作为 fragment_assembler 的固定冒烟用例：

```
输入：  "我为哪些模型命过名？"
期望：  ① 别名解析：暮暮/蒸馏仔 → canonical 归元仔（同一体）
        ② 实体锚：distiller-agent 实体存在（该个体唯一锚，非平行实体）
        ③ 消歧：暮暮命中[旧名] 与 [团队角色] 时输出冲突提示，不硬合并
        ④ 缺口：明确"2026-06~10 无记录"或未查到的段位如实标注
```

## 五、风险提示（用户强制写进文档备注）

1. **范式不能凭空创造事实**：必须依赖元数据地基。只有范式没有别名/实体锚，会直接降级回关键词横扫（= 现在这三次的原始状态）。
2. **消歧是硬红线**：遇到多义名字（如"暮暮"）只告警，不强行合并实体，避免把不同人/不同概念混在一起。
3. **缺口必须显式输出**：禁止脑补填充，恪守记忆系统"不编造"原则。

## 七、已知观测 / 待办

- **暮暮歧义**：数据里"暮暮"确有两义（旧名 / 团队叙事解构师），本次保留"旧名→归元仔"映射，但这是**消歧红线该告警的活样本**。当前 `resolve_alias()` 能检出**别名表内**的多义（同一 alias→多个 canonical），但"暮暮作为团队角色"这一义尚未建独立实体锚，故 `resolve_entity()` 目前只归到 distiller-agent 单实体——**角色义属真实缺口，已在缺口显式标注范畴，需后续决定是否为三人团队成员各建实体锚**。
- **core_term_alias 已接通**：`memory/entity_resolve.py` 提供 `resolve_alias()`（别名归并+多义告警）与 `resolve_entity()`（实体锚查找，含 summary LIKE 兜底），已对外部裸连接做 row_factory 防御。回归冒烟：暮暮/蒸馏仔/归元仔 → 均归一 distiller-agent；无实体时返回降级提示。
- **阶段3 边界**：本阶段只做「范式 + 数据地基 + 别名读取」，**不做完整问题拆解/路由/答案组装**（那是阶段3 路线C）。
