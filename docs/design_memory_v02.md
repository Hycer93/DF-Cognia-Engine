# 记忆模块 v0.2 设计方案：三级存储 + 树形编码 + 定期整理

> 定案日期：2026-11-06。设计来源：两份专利（可复现性三级判定 + 树形统一编码权重内化）× 主AI三处修正 × DS 两轮联合设计（logs/ds_memory_consolidation_r1/r2.txt，主AI四点质疑全被接受）。
> 状态：设计冻结，待实现。memory.py 72 行 → 目标 ~400 行（含 memory_organize.py 整理脚本 ~150 行）。

## 1. 总架构：两专利正交拼合 + 整理层

```
对话/交互内容
 ① 三树编码（领域+行为+关联[+感性三树可选]）→ 结构标签
 ② 可复现性判定（行为树编码预筛短路：计算/检索类节点直接判一级；感性树有标签≈必为三级；只对模糊带调判定单元）
 ③ 分级落库：
    一级 → 可推导数据层（原knowledge_v3改造）：只存检索入口+三树编码，不存本体
    二级 → 情景摘要层（flash_v3新子层 tier=summary）：压缩摘要
    三级 → 闪念记忆层（flash_v3 tier=active）：全量原文+全树编码+适用性元数据（时间戳/是否被推翻）
 ④ 召回 = 编码匹配 + 四维加权（编码匹配度/置信度L0-L4/调用统计/关联激活度）
 ⑤ 反馈迭代 = 有效上浮1.08-1.15 / 无效衰减0.82-0.90（赫布更新已有，参数对齐）
 ⑥ 定期整理（本方案核心增量，见§3）
```

## 2. 对 memory.py 现状的改造映射

| 现状 | 缺陷 | v0.2 处置 |
|---|---|---|
| save_flash 收 QA 摘要 | 非资产，判定标准是"是否轮末"而非"是否可复现" | 门口加可复现性判定；三级资产才入 flash |
| knowledge_v3 只读不写空转 | 每轮查询空库纯开销 | 改造为可推导数据层：一级条目=检索入口+编码；当前空库阶段查询短路 |
| chat_v3 全量归档 | 与闪念层职责重叠 | 保持归档不变（三级原始现场，永久） |
| 无遗忘/整理 | flash 只进不出，top_k 被平庸摘要淹没 | §3 整理机制 |
| 召回无适用边界 | 过期结论可顶掉新推理 | 三级条目强制带 metadata: {timestamp, superseded(bool), tier, cluster_anchor} |

## 3. 定期整理机制（DS 两轮定案 + 主AI修正）

### 3.1 触发器（三路并行）
- **T1 条数阈值 [实测待定]**：flash count > 实测拐点（初始先验 800，Week1 用现有库跑"条数 vs top5 稀释率"曲线找拐点替换）
- **T2 质量触发（双信号源）**：
  - 交互场景：追问率>15% [先验-业务设定] 或 top2 余弦中位数<P25 实测 [实测]
  - 自动化场景（攻防/探针，无用户信号）：同 query 相邻两次 top2 Jaccard<0.6 [先验-业务设定]；或注入利用率<20%（回答引用 top2 字符占比，无监督代理）
  - 按 ask(interactive=True/False) 切换
- **T3 定时兜底**：每周轻量整理（仅去重+补链，不合并）

### 3.2 操作集（代价升序）
- **Op1 去重**：simhash Hamming≤3 判重，重复条目 tier=precedent + superseded_by（可回溯不常驻）——零信息损失先上线
- **Op2 合并**：行为树编码一级键分桶，桶内 embedding 层次聚类（阈值 0.82 [实测：抽 20 簇人工判该合/不该合画 PR 曲线]），簇→结构化资产 {模式名/触发条件/标准流程/边界反例/来源ID链}；编码漂移>30% 放弃合并
- **Op3 固化**（改名，原"升维"被主AI质疑后修正）：命中≥3 的资产 flash 内 tier=merged→asset，**自动链路永不写 knowledge**；跨集合升级须人工门禁+derived_from 链
- **Op4 降级**：合并后旧条目 tier=precedent，检索默认过滤，trace() 可回溯——不删（兼容专利A三级不可复现全量永久 + 情感向量"原谅=降级为沉默"哲学）
- **Op5 关联补链**：新资产在关联树补边，权重=簇内关联激活度均值×0.9（整理是压缩非新增证据）

### 3.3 实体级幂等（DS Q1 修正采纳）
- 新增 memory_clusters 表（SQLite 旁挂）：簇锚 ID = uuid5(行为编码+关联编码+桶创建时间)
- 增量整理：同锚已有资产且新碎片 sim≥0.82 → 并入（权重=(旧×旧数+新均值×新数)/总数×0.85）；<0.82 → 同锚子资产，检索时同锚互斥去重（top_k 内同锚只留最高分）
- 资产 ID = 锚+子模式序号确定性生成——同簇收敛有限资产，不随碎片增长膨胀

### 3.4 保护清单（硬保护，命中即 skip）
held_out=True / evidence_chain=True（账本级证据链）/ skeleton_lineage 非空（27 骨架血缘条目）/ tier=precedent 且 merged_into 被引>10 次 / 最近 7 天有 last_cited 更新

### 3.5 四维权重参与
- 整理候选按综合权重升序，<P40 [先验-可校准，按月分位数重算] 优先去重/合并；>P80 只补链不合并（稳定资产不损失细节）
- 合并产物初始权重=簇内均值×0.85，后续靠调用统计自然回升——整理不制造虚假权重

### 3.6 验证与止损
- 整理前后各 7 天滚动指标：top_k 命中率（+≥10% 目标）/人工抽检查准（≥3.8/5）/上下文占用（-≥30%）/回溯完整率（100%）
- **回归门禁**：命中率降>5% 自动按 op_id 逆序回滚
- 回滚机制：整理只标记+新建不物理删除；before_snapshot 存 memory_ops 表

### 3.7 常量分级（DS Q4 修正采纳）
[实测]（Week1 出数替换）：800 条拐点 / 0.55 余弦线 / 0.82 聚类阈值
[先验-可校准]（按月权重分位数重算）：0.4 低权重线 / 0.75 高权重线
[先验-业务设定]（按误报率调）：15% 追问率 / 20% 引用率 / 0.6 Jaccard

## 4. 用户终裁修订（2026-11-06 第二轮，五问题裁决）

### 4.1 教材/记忆分离（问题1+2 定案）
- **教材=三级不可复现**（判定依据=交互现场不可复现，与可复现性哲学自洽）
- **本地 jsonl 是 source of truth，ChromaDB 只是投影**：投影层任何损失可从本地重建（整理误伤从致命降为可恢复）
- 分离实现：记忆标签加 `asset_class: corpus | runtime`；corpus 类整理机制硬跳过（对练样本/教材血缘含于此）
- **多轮审查版本控制**：重要记忆（权重>P80）覆盖需 2 轮审查、间隔≥7 天，通过才提交新版本，旧版本进版本链不丢弃；轻量记忆单轮——分级审查：越重要越慢

### 4.2 记忆图结构：原子层+经验层（问题3，用户方案优于主AI原"整组归档"案，全盘采纳）
```
原子记忆（单话题，标签+ID；多话题入库时拆原子+关联边）
   │ ID 关联记录：A→B 前后件 / A↔B 同话题 / A⊗B 对冲
经验层（新增，非覆盖）：经验条目带 derived_from:[原子ID列表]
```
- **经验是新增不是替代**：错误经验衰减后，原子记忆恢复独立可召回（经验死活不传染原子——两物理层）
- **删除门槛**：删除提案需连续 2 个整理周期无关联链引用 + 通过"删掉它哪个骨架血缘会断"检查，任一不过只降级不删；删前自问制度化

### 4.3 反向教材标签（问题5 定案）
- memory-tag 新增 `polarity: positive | negative`
- 检索规则：normal 召回默认过滤 negative（不污染判断）；复盘/教学场景显式开启 negative 通道（错误=不进主路旁观的教具，与 S1 伪纠错负例库同哲学）
- 同步建议 DFCP memory-tag schema 增补此字段

### 4.4 快通道预注册验收（问题4 同意，待办）
- 需设计"加权召回 vs 纯语义召回"对比探针（多信息并置类场景），评判标准跑前写死——防止以后快通道效果归因不清

### 4.5 DS 第三轮整合（用户五裁决 × 整理机制兼容性对撞，2026-11-06）
DS 原文：logs/ds_memory_consolidation_r3.txt。五 Q 全裁决 + 双层架构操作集总表：

- **Op2 改制**：合并只产出经验层条目（derived_from=原子ID列表，polarity 继承多数派），原子层只打 referenced_by 不被合并。簇锚迁移为"经验簇锚"，键=(行为编码,关联编码,**polarity**)——正负经验永不同锚
- **DS 新发现缺口 3 个（采纳）**：①单经验 derived_from 上限 50，超限分裂子经验（防经验退化为话题桶）②R2 版本链须"待审版本不参与召回"（7 天审查期语义分裂漏洞）③跨通道同原子去重取 max（通道隔离后同原子占两坑位问题）+ 分层指标冷启动 14 天 warmup（样本稀释期只用融合段触发 T2）
- **权重隔离**：原子/经验两套独立计数器分层计算；错误经验不连坐原子权重，仅临时下调该原子的"经验引导通道"权重（通道隔离非权重连坐）
- **negative 经验禁固化**：tier 永 ≤merged 不进 asset/knowledge（固化=强化召回，错误模式被高频召回是风险）；合并须保留≥2 条原始原子 ID 防追溯丢失；不触发 R2 审查队列
- **指标三段拆**：原子直召段/经验引导段/融合段，ask() 按来源分段记账不混算
- **DS 移交用户的一个真问题（待裁）**：polarity 是否只挂经验层、原子恒为 neutral？——DS 建议是（原子无正负，正负是经验属性；否则 normal 过滤会误伤原子直召）。**影响 Op1 标签写入及 Q4/Q5 全下游**

### 4.6 用户第四轮裁决：摘要/详情/原始语料三层结构（2026-11-06，今日最大增量）
```
摘要层（一句话总结）——检索唯一入口，量少而精
   │ 1:N 绑定
详情层（详细内容+记忆由来）——经验实际载体；错误教训记在"由来"段，不上摘要层
   │ 1:N 绑定
原始语料层（出处原文）——只管可回溯，永不参与检索
```
- **碎片化的根源是检索入口和存储内容混层**，三层分离后"一记忆带一片"只在显式下钻发生（用户主动要的）
- **每日整理核心动作**：①摘要层间关联重判（该合的合/该拆的拆）②详情池跟随重组重聚类③详情重新绑定原始语料 ID（重组后溯源链不断）——每日整理是重中之重，非阈值触发兜底
- **审查期裁决（推翻DS"待审不参与召回"）**：**乐观更新**——新版即用，旧版进对照区，每日自检时对比确认，新版错则回滚。审查从阻塞式变并行式，污染窗口≤1天由每日整理节奏压住。旧版意义=自检对比基准+回滚兜底
- **错误经验占坑位问题（结构化解）**：错误教训放详情层由来段，**不占摘要入口**→normal 召回从结构上碰不到（比 polarity 过滤更彻底——没有入口，无需过滤规则）；反向复盘（"最近哪类老错"）走专用 query 扫详情层由来段，非标签体系
- **polarity 字段裁决**：三层结构让 DS 移交问题（polarity 挂哪层）自动消失——原始事实在语料层（永不检索）、错误教训在详情由来段（不进入口），每层放什么由层职责决定，**polarity 字段裁撤**（DFCP schema 增补建议同步撤销）
- derived_from≤50 上限问题被三层结构消化：经验退化成话题桶的根源是入口与内容混层，分层后不再需要硬上限（超大自然簇=摘要该拆分的信号，交给每日整理）

### 4.7 用户第五轮裁决：三级↔三层是嵌套非映射（2026-11-06）
**主AI原"正交两维度"表述错误，用户纠正：判定三级与结构三层是上下级嵌套关系。**

```
判定层（管预算）：flash / situational / derived
 ├─ flash（不可复现）→ 三层全占：summary + detail + source 全量永久
 ├─ situational（条件可复现）→ summary + detail 占用，source 层只存受限源入口
 └─ derived（完全可复现）→ 仅 summary 层；source = 检索路径指针，非内容
```

- 判定三级决定记忆对三层的**占用权限**（预算）；结构三层决定预算内组织方式——是包含/裁剪关系非正交组合
- 该关系取代此前一切"映射表"方案（DS r2 的专利A↔DFCP 跨体系映射随之简化为嵌套内部自洽）
- 连带圈定："错误教训放 detail 由来段"规则自动限定于 flash/situational 级（derived 无 detail 层）——作用域由结构圈定无需额外说明
- asset_class 确认为护栏字段非类型学：教材与 runtime 记忆内容属性 90% 相同，差的是生命周期规则（SDD管 vs 整理机制管）；护栏同时服务于投影重建（混合 jsonl 无法分别重建）

## 6. 用户第六轮裁决：三层分层架构定案（2026-11-07，取代旧 Op 编号体系）

**总原则**（用户方案全盘采纳）：底层账本刚性、可审计、可复现；相似/同源/冲突是上层认知关系算子，不侵入主键；仅 ≤200 字摘要 + DFCP 编码参与相似度加权比对，详情与原始语料不参与，隔离污染范围。

### 6.1 ID 体系（刚性底层，永不妥协）
- **inst_id** = uuid4()：单条记忆实例主键，写入后永久不变（身份与内容解耦）
- **full_hash** = 摘要+详情+原始语料合并哈希：精确副本拦截、版本校验
- **dfcp_tag** = [域-子域-场景|行为|关联]：相似判定强先验过滤（**极性字段彻底移除**——裁决1：结构性隔离已替代其功能）
- **entity_id**：认知本体链编号，**关系层非主键**；同源多实例挂同一 entity_id，支持分叉/冲突分支

### 6.2 三层分层（裁决3：新命名承接旧职责，旧 Op1/Op2/Op3/Op5 编号废弃）

| 分层 | 承接旧职责 | 职责 |
|---|---|---|
| **原子存储层**（原 Op1） | 入库 | 写入记忆实例、inst_id、full_hash、三级文本、dfcp_tag；精确去重、账本、审计、版本快照 |
| **认知关联层**（原 Op5 关联补链） | 相似召回+本体链 | 摘要向量+DFCP 过滤、同源判定、冲突打标、entity_id 本体图谱维护 |
| **经验聚类层**（原 Op2 经验合并） | 沿链归纳 | 沿 entity 本体链归纳提炼稳定经验、构建 derived_from 溯源链、生成可蒸馏思维轨迹 |

### 6.3 四档关系判定（认知关联层入库分流）
高重合→复用本体仅计数；中高相似→同源增补挂 entity_id；中等相似→同源分叉冲突打标送冲突/前置假设评审流水线（接元思域矛盾对撞）；低相似→新 entity_id。
关系图谱独立存储，可单独关闭/重算/回滚不伤账本。**图谱条目强制带 computed_at + embedding_base 两字段**（认知不幂等代价的对策：判定结果是库状态函数，须可复现当时基线）。

### 6.4 摘要契约
200 字上限入[先验-业务设定]常量分级表（裁决2：不写死硬编码字面常量，移入全局常量表）；"截断"改"收敛"（压缩改写保主干，非砍尾）；仅核心观点变更可修改摘要，微调论据/排版禁止改动；修改生成新版本保留旧摘要（乐观更新+对照区已定，无冲突）。

### 6.5 固有代价四条（明确边界，方案自承认）
短摘要歧义假同源漏召回（DFCP 硬标签降概率不根除）/ Embedding 基座更换向量漂移（冻结校准集定期巡检）/ 认知层面不幂等（同记忆不同库状态同源判定可能不同）/ 摘要修改契约与分域阈值长期维护。

### 6.6 用户第七轮裁决：教材在认知关联层彻底隔离（2026-11-07）
- 裁决 A（vs B 可作候选但不下冲突结论）：**corpus 教材既不作判定新条目，也不作被比对候选**——四档判定只在 runtime 内部发生
- 理由：教材=三级不可复现的冻结现场，是字典不是对话对象；runtime 引用教材走 origin_ids（A→B 前后件），不产生同源/冲突语义
- 收益：污染范围最小化——关系图谱错误永不波及教材层

### 7.2 换嵌入基座强制流程（风险1对策，不可跳步）

### 7.3 as_of 切片语义（2026-11-09 用户裁决=B 认知视角，已实现）
- **B 认知视角（定案）**：按 event_ts ≤ as_of **AND** ts(入库) ≤ as_of 双过滤——回答"当时的我知道什么"：事后补录（5月事件11月入库）不出现在5月切片，按入库时间归位到11月切片。
- 已实现于 `memory_query.entity_evolution`；边界明示于 docstring：只看当时已定稿入库的记忆，未定稿草稿讨论天然看不到，**不承诺完整复原当时全部思考过程**（风险5）。
- 附带发现（实测）：认知引擎实体 24 条成员全部 2026-11 入库（考古回填性质），B 视角下 5/31 切片=0——这正是 B 的正确行为：5月底的"我"库里还没有这些记忆（当时只存在于对话历史）。A 视角 19/24 是把事后考古穿越回填，语义确有差异。

### 7.5 二级备用标签：用户反馈沉淀制（2026-11-09 用户裁决，取代预填别名表提案）
流程（用户原话提炼）：**不从外部预填别名；别名来自真实用户查询-命中反馈；失败先如实说不知道，不猜；成功之后才沉淀。**
```
① 用户用代号/别名查 → 匹配不到 → uncertain/marginal_ask/empty 如实返回+反问（不瞎补关键词）
   └ query 挂起 alias_pending.jsonl（TTL 24h，纯寒暄 match_eff≈0 不挂）
② 用户换词重问 → hit（确凿命中才算，边缘带不配对——宁缺勿滥）
③ 配对判据：失败查询与成功查询 2-gram 余弦≥0.15（话题延续）或 2-gram 子集（换词重问形态）
④ 原始失败查询的实词 → 沉淀为该记忆的二级备用标签（alias_tags.jsonl 叠加层，append-only，
   带 origin:user-feedback + derived_from_query/paired_with_query 全程可溯）
⑤ 下次旧别名查询 → 别名词并入 kw 匹配池直接命中（只提召回，门控公式不动）
```
实现：memory/memory_alias.py（record_miss 挂起 / try_pair_on_hit 配对沉淀 / alias_lookup 检索辅助），
memory_query.ask 挂三个钩子。

**实战事故与双保险（上线首日就抓到）**：测试期间泛指查询"我们之前讨论的那个方案定了没"也走挂起→配对，
会话套话（"方案定/们之前讨论"）被沉淀成别名，**借别名表绕过反问门**把泛指查询抬过 0.22 线（gate 回归 14/15 红）。
修复双保险：① 提取侧——GATE_ANCHOR_STOPGRAMS 套话词含其中即整段丢弃（该查询现提取为空[]，无别名可沉淀）；
② 匹配侧——别名池进 _keyword_score 同样走停用词过滤。修复后 gate 15/15 全绿，泛指查询 me=0.1758 重新被拦。
教训入档：**任何提升召回的新通道，都会成为绕过门控的新后门**——新通道必须复用门控的停用词纪律。

**v2 定案：六条件 ALL + 三层防御（2026-11-09 用户五风险裁决）**

用户挑战 v1 停用词黑名单方案："不是理解这大概率不是关键词，这跑多了翻墙的还是会有，且检测名单还需要不断迭代，也不可靠"——字面枚举不可靠，必须结构性判据。
由此升级为三层防御（黑名单只是头道筛，不再是安全边界）：

| 层 | 机制 | 职责 |
|---|---|---|
| L1 停用词粗滤 | GATE_ANCHOR_STOPGRAMS + 疑问尾巴/时间词/功能词开头段丢弃 | 拦大头，**非安全边界**，漏网交 L2 |
| L2 弱交集结构验证（C5） | 候选词与目标记忆实体文本池 ≥1 个 2-gram 重叠 | 结构性判据：套话与记忆实体零重叠，黑名单失效也拦得住 |
| L3 生存验证 | 30 天零命中 → 读侧失效（expire_inactive 状态标记，**不删物理行**）；命中即续命（op=hit 追加） | 错沉淀自愈 + 人工可 reactivate 复活 |

**实体文本池**（C5 比对面）= 摘要 ∪ 旧别名（含失效）∪ 同 entity 链邻居摘要；无 entity_id 时退化为摘要 ∪ 旧别名——
"没上户口也允许起外号"（用户风险1裁决：classify_and_link 未跑的记忆不能因缺 entity_id 被拦掉合法别名）。

**C5 弱交集口径（用户风险2裁决）**："沾边就算，不是严格完全匹配"——只要部分 2-gram 重叠即通过。
例：记忆「SPI 调试模块」vs 用户说法「SPI 硬件注入调试组件」→ overlap=['PI','SP','入调','注入'] 通过。
实测压测：L1 黑名单失效场景下，'方案定'/'我们那个讨论'/'上次说的那个事情'/'方案确定了没有' 全部零重叠被 C5 拦；
真别名 'SPI硬件注入调试组件'/'信号注入工具'/'车机信号调试模块' 全通过。

**配对六条件（ALL 语义，少一条拒绝写别名——严禁改代码放松成"满足其中几条"）**：
- C1 失败提问在挂起池 24h TTL 之内
- C2 本次查询确凿 hard-pass（me≥0.22），边缘带不配对
- C3 前后两次提问 2-gram 余弦 ≥0.15（话题延续）
- C4 停用词粗滤后候选词非空
- C5 候选词与目标记忆实体文本池弱交集 ≥1 gram
- C6 目标记忆非受保护（skeleton_lineage / evidence_chain / held_out）

沉淀记录（alias_tags.jsonl，append-only）带 conditions_passed 六条件快照，全程可溯。

**30 天失效（用户风险3裁决）**：只是"不让它参与打分"，绝不物理删行——append-only 纪律，历史证据留档排查；
失效别名 E4 巡检可见，人可 reactivate_alias 手动复活（复活即续命起点）。

**Week2 换向量基座待办（用户风险5裁决）**：C3 的 0.15 与 C5 交集判据均基于 char-2gram 经验值，换语义向量后
① 0.15 门槛重新标定；② C5 交集判断可升级为语义相似度；③ **三层防御整体架构保留不变，不要直接把整套逻辑丢掉**。

E4 巡逻追加第9项：别名表健康（脏别名=含停用词的历史沉淀，读侧已拦但表内该清理；挂起池积压量；30天失效别名的物理行计数——供人决定是否 reactivate 复活）。

### 7.6 memory_class 判定样例（件② 2026-11-10 用户终裁，schema 契约配套）

**定位回顾**：五类不是万能分类，是「高价值、会主动参与蒸馏/归纳/经验复用/复盘检索的特殊记忆角色」。不属于五类的记忆 memory_class=null，null 是合法值（普通记录），不是待修的脏数据。

**判定规则（与 schema.py / memory_judge.py 同步）**：
- 校验只拦白名单外字符串；null 放行
- Q3 判定卡：内容明显属五类但为空 → class_missing_suspect 嫌疑标记交人工复核，不卡入库；普通记录主动允许 null
- behavior 先验仅 Q3 可疑提示，非硬拦截
- 结构性判断非字面：judge 基于内容判「是否值得作为可复用经验资产」，特征词只做粗筛

**样例对照**：

| 样例 | 判定 | 理由 |
|---|---|---|
| SPI 调试事故复盘 | scar_case | 事故→根因→修复的完整教训资产 |
| 阈值调优（W_MEMORY_CLASS=0.05 锁定） | skill_refine | 参数级经验，可复用到同类标定 |
| 架构路线更换（四维→五维升级） | strategy_evolve | 路线级决策演进 |
| 编码契约（摘要双词规约：实体锚点+上位概念词） | key_pact | 检索/编码层的强制约定 |
| 实体关联打通（蒸馏仔建库） | relation_milestone | 实体血缘节点 |
| 单纯聊天记录 / 临时观测 / 中间读数 / 随手备注 | null | 普通存档，不参与专项归纳 |

**禁止事项**（S015 裁定）：
- 不设 other/miscellaneous 兜底大类——会稀释五类筛选价值
- 不随便扩充枚举——新增一类必须走完整裁决并四处同步（schema/judge/文档/E4 巡检）
- 不硬塞：E5 回填提案不属五类时直接提 null

**防御机制**：E4 巡检指标 high_value_content_without_class——特征词命中但 memory_class 空的条目输出报警（不拦截），防止高价值记忆被随手标空废掉分类。检索侧 null 维度匹配分归零不扣分（W_MEMORY_CLASS=0.05，命中纯增益不进分母）。


### 7.7 外部权威校准工位（风险7 对策，2026-11-10 DS 两轮对碰定稿，logs/ds_calibrate_r1/r2.txt）

> 起因实战：历史语料考古入账 25 条专利账+1 条版本史，自建编号与真实持有方（归元仔）真实编号系错位；
> 考古语料止于 5 月、实况已演进 5 个月（16 件已提交 vs 考古口径 7 件）。26 条降级为沉默，零删除。

**实体层**
- 校准单 = 一等实体：字段集 `inst_id / status(draft·pending·approved·rejected·superseded) / external_anchor / participants[] / reason / created_at`
- external_anchor 必填（专利局编号/官方文件），纯对话声明不算数——校准单的权威性由外部锚点校准，断无限回归
- 条目加 `provenance ∈ {verified, inferred, speculative}`：正交于 tier/判定层，不开新体系（DS R2 纠正 R1 的 tier=speculative 误写）
- **门禁2（事故真根因前置卡）**：考古入账强制 `provenance=speculative + corpus_snapshot_date`；升 verified 须过显式核对动作

**写操作层**（已实现 memory_organize.demote，2026-11-10 自测三态全绿）
- `demote(inst_ids, superseded_by, reason, calibration_source)` 返回 `{applied, skipped, conflicts}`
- 三态语义：superseded_by 空→applied；相同→skipped（真幂等）；不同→conflicts 整批回滚不写，抛调用方裁决，**不自动追加链**
- **门禁1**：批量降级（>1 条）强制 calibration_source，缺失拒绝
- supersede 链上限 8 跳（supersede_chain_length 检测），超限报警不自动合并
- 反向索引替代事件节点：校准单 participants[] + 条目 superseded_by 互指一跳可查——前提=校准单为一等实体（DS 前置断言，Week1 第一件）

**调度层（nightly 三态，防同步死锁）**
- 可自动：≤N 条 + superseded_by 明确 + 无 conflict → 自动 demote + 审计 + 晨报「请复核」
- 挂起：大批/conflict/整片推翻 → 校准单 status=pending（查询即队列，**不建独立队列文件**），nightly 不阻塞
- 禁止自动：删除/tier 升级/跨层重构 → 硬拒绝仅人工
- pending 超 X 天 → 升 E4 high 级报警（复用现有通道，不新建）

**运维层**
- 恢复路径：.bak_demote_* 按 inst_id 过滤回写，写进 §7.4 夜间清单提及，不单独立项

**学习层（Week2+，依赖门禁2 动作定型）**
- SFT 蒸馏「考古入账→显式核对」动作序列，不蒸馏「快照会过期」陈述（知识≠动作，DS R1 打中）

**固有代价（认了）**：pending 积压靠超时告警兜；门禁2 拖慢考古入账（安全换速度）；反向索引依赖校准单一等实体先落地。

**实施顺序（DS R2 收敛）**：校准单一等实体 → 门禁2(provenance 字段) → demote 三态(已实现) →(夜间)三态分流+链上限+门禁1 →(Week2+)SFT 动作序列蒸馏。
