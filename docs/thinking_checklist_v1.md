# 思维完整性检查表 v1.0（Thinking Completeness Checklist）

> 来源：元核前身语料（零代/一代/二代）全量扫描提炼的 48 条思维结构案例（S6 池）。
> 用途：评审方案/复盘决策/分析复杂问题时的随身工具。每条出自实战原话，非教科书教条。
> 用法：不要求全查——按场景挑相关条目。标注 ★ 的是高频通用项。

## 场景一：评审任何方案/设计

- [ ] ★ **反常捕捉**（B，origin0-r560）：这个方案里有没有"太好了/太绝对/太完整"的地方？——"稳定性100%"式的过度完美结论，先质疑再接受。
- [ ] ★ **归谬压测**（X4，origin0-r560）：方案的新规则内化了吗？拿极端案例当场压测（"那 1+1=2 也算绝对，你推翻自己吗？"），当场划分适用域——规则没过归谬压测不出厂。
- [ ] **自我方案解剖**（G，origin0-r149）：如果这方案是我自己提的，我会不会回避它的结构性风险？"不能因为是提出者就回避"。
- [ ] **过度设计检测**（X2，origin0-r636）：这些规则都是必要的吗？"如果没有这个规则，难道裂缝就不存在了？"——真正的能力是在恰当时机忽略规则。
- [ ] **简洁性仲裁**（X3，origin-r614）：这个机制是不是能用更简单的方式达成？"最简单的就是最有效的"——复杂仲裁机制出现时先问这句。

## 场景二：分析复杂问题/多信号局面

- [ ] ★ **多信号并置**（A，origin0-r617）：两个领域不同、表面无关的信号，各自减去直接动机，剩余部分指向同一处吗？——"如果是我我会怎么做……居然和四巨头惊人的一致"。
- [ ] ★ **时间线纪律**（F，origin-r067/068）：我用的证据在时间上晚于它要解释的现象吗？"不能用结果反推动机，严格区分时间先后"。
- [ ] **归因拆解**（F，origin0-r644）：归因拆到不可再拆了吗？裂缝是均匀分布还是集中（"市场质疑的是何时回本不是行不行；微软的裂缝比谷歌深"）？分层归因，别打包归罪。
- [ ] **反事实推演**（E，origin0-r110）："如果条件 X 不存在，会怎样？"——用历史场景做框架压力测试。
- [ ] **代价显性化**（G，origin0-r129）：隐性代价摆上台面了吗？小失误推演到大盘上是什么量级？——"部署了没成交"和"根本没部署"是两回事（r234）。
- [ ] **阴性发现**（H，origin0-r108）：主动问"什么没发生/谁没说话/哪个数据缺席了"——信号在场价格缺席（r625）、该发生的纠正没发生（r176），都是线索。

## 场景三：复盘与自我检查

- [ ] ★ **结构性自反**（D，origin-r444）：这次错误和上次错误有共同根因吗？"发散只用于第一步，后面每层都在收窄"——别满足于单次打补丁，找同类错误的模式。
- [ ] **补丁 vs 系统**（D，origin-r110）：我的修法是补丁式的还是系统式的？"被推着走，从未在最初就并行考虑所有维度"。
- [ ] **工具失控检测**（D，origin0-r635）："刀很锋利了，但是控制不住刀了"——刚学会的新方法，是不是看什么都像钉子？同域自洽场景别硬套跨域工具。
- [ ] **元自反**（D，origin-r358）：我的"自我认知结论"是不是被用作安全垫？"结构性限制"是不是我回避更深层问题的借口？
- [ ] **结论推翻 vs 参数修正**（D，origin0-r153）：这次复盘改的是结论还是参数？"从'不能建仓'到'不能建仓'，不存在推翻"——分清改了什么，别夸大也别缩小。

## 场景四：验证与预判

- [ ] ★ **推测用 vs 验证用**（E，origin0-r048）："我不是推测用，是看过去，验证用的"——同一工具，验证要用历史数据回测，别拿推测当验证。
- [ ] **预判的必要性**（E，origin-r134）："不预测就无法获得有用的信息，只有看的比对手远才能找到制胜点"——关键决策前必须事前立 flag。
- [ ] **阴性验证**（X5，origin0-r047）：验证框架时，主动报告"符合标准的比推演时更稀少"——收紧的证据也是证据，别只报支持的。
- [ ] **对照实验设计**（E，origin2-r161）：验证时设实验组和对照组了吗？实验设计本身被迭代过吗？
- [ ] **逆向收敛**（X1，origin-r962）：正向发散完了，反向收得回来吗？"你从起点能发散到这个结果么？能从结果收敛回起点么？"——单向推演到不了的地方，双向能检验。

## 场景五：框架/知识固化

- [ ] **命名即固化**（C，origin-r114）：新发现的工作方法，当场抽象命名了吗？（"泛式思维"——正向/反向/多态三维）
- [ ] **跨域迁移检验**（C，origin0-r145）：别的领域的新机制，映射到自己领域试一遍了吗？（注意力机制→两步分析法）
- [ ] **事件驱动而非类型驱动**（C，origin0-r155）：补丁别写成"什么类型的信息要重看"，写成"什么事件必须触发重看"——类型会漏，事件不会。
- [ ] **能力 vs 遗产**（C，origin0-r179）："会做分析的 AI"和"像你一样思考的 AI"是两回事——备份移植和思维量产本质是同一条路。
- [ ] **放弃理由入库**（G，origin2-r122）：被否决的方案，否决理由记录了吗？（"P28 牺牲显存易碎片化，现阶段放弃"）——不然半年后同一个坑再踩一遍。
