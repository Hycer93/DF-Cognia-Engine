## 3. 回滚可行性审计（三层实测）

### L1 — 环境变量快速降级 `DF_SUMMARY_EQUIV_DEDUPE=off`

实测（现网库副本）：
- `MODE=off`，近似卡写入 → `stored`（正常入库）
- `gate_log ops=[]`（**零 P0 日志，完全退回改造前**）
- 精确副本二次 write → `replica`（full_hash 查重仍有效）

**结论**：off 态 = 改造前行为，可秒级降级，零残留。 ✅

### L2 — dry-run 只观测不拦截

实测：
- 高相似写入 → `stored`（**不拦截**）✅
- dry 日志 `would_skip=True`（观测到但放行）✅
- **无** `skip_equivalent_derived`（未真拦）✅

**结论**：dry-run 纯观测，可用于生产灰度收集数据不影响写入。 ✅

### L3-L4 — git revert 单步回退

实测：`git revert --no-commit` 对 C3/C4/C5 均可干净反向（commit-2/3 共享 memory_organize.py 但 git auto-merge 通过）。

**数据回滚评估**：本改造无 DDL、无存量改数据；回退后仅"新写入行为"恢复旧逻辑，**已入库数据无需回滚**（derived_only 标记随卡存在，off 态不读它无副作用）。 ✅

**方法**：复制现网库到 tmpdir，用池中每条（n=280）真实 summary 作为"模拟新写入"逐个比对池（排除自身），完全走 `_p0_equiv_check` 同款 embedding+matmul 逻辑。现网库零污染。

### 4.3 命中样本人工核验（关键：假阳性率）
