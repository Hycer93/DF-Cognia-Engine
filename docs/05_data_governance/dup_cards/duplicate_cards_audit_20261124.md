## 三、根因（B 类 21 组的成因）

B 类是 **隔离区修复脚本 `fix_quarantine_20261123.py` 的副作用**：

```
隔离区 jsonl 里同一张卡有多个分片记录(如 #18/#19/#20)
  → fix_quarantine 各 re-ingest 一次
  → full_hash = hash(summary + detail + source_ref)，source_ref 带 #序号 → 三份 hash 各不相同
  → full_hash 精确去重失效 → 3 份全放行入库
  → P0 语义层才发现 summary 相同 → 写 would_skip=true（这就是 P0 计数虚增来源）
```

**full_hash 去重的盲点**：它假定"source_ref 不同 = 内容来源不同"，但隔离区恢复时 `#序号` 只是同一条记录的分片编号。这是设计缺陷，值得记一笔。

## 七、P24 原卡降级原因（已查清）

**原卡 de064720 的 `superseded_by = 44d69231cca949789dee2925c776b9b9`**

指向的卡：
```
44d69231 [外部校准]归元仔真实专利总账P1-P43共40+件
         (2026-11-10对齐,推翻考古25条口径)
         tier=active, source_ref='用户对齐'
```

**降级真相**：
1. P24 原卡（de064720，11-09 入库，来自 patent corpus）在 **2026-11-10 被"真实专利总账校准"降级为 precedent**——因为用户核对了真实专利编号系到 P43，推翻了旧的"考古 25 条"口径，P24 的原始摘要被判定为"旧口径版本"，保留为采信先例。
2. 这是**合理的版本演进**，原卡降级是**本意**，不是错误。
3. **但问题在于**：隔离区 jsonl 里对该专利有 **3 条重复记录**（行17/18/19，都是"非法可复现性: verified"被拒的同一卡），fix_quarantine 逐条 re-ingest，造出 3 张 active 副本(#18/#19/#20)——**这 3 张 active 是误入的**，它们让"已降级"的摘要又冒出 3 个 active 版本，污染了 active 池。

**结论**：P24 组应删除 3 张 Q active 副本，**保留原卡 de064720（precedent）**。删后该摘要只剩降级卡，符合 11-10 校准后的正确状态。**无需恢复 active**——原卡降级是对的。
