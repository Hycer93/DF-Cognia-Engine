### 缺陷①根因（两层同源 bug）

**层 1 — F10 裁剪**（`future_sim_minloop.py:161`）：
```python
branches = [b for b in branches if b["weight"] >= CONFIG["branch_prune_w"]]
```
conflict 边 `δ=-0.8` → `w=(1-0.8)^β`，三档 β 下：
| profile | β | w | vs prune_w=0.3 |
|---|---|---|---|
| conservative | 0.6 | 0.38 | 过 |
| **baseline（默认锚点）** | 1.0 | **0.20** | ❌ 裁 |
| exploratory | 1.6 | 0.08 | ❌ 裁 |

→ **默认 baseline 下任何 conflict 边必被裁**。conflict 被代码明确定义为"反向/矛盾分支"，是发散方向之一，数学上却永远出不来——**F10 自相矛盾**。

**层 2 — F20 `factor_edge` 编码不一致**（`f20_weight.py:113`）：
```python
return EDGE_W["rel"] if (etype or "").startswith("rel") else EDGE_W["topic"]
```
F10 产**裸** `rel="new"/"conflict"/"augment"`，F30 内部产 `"rel:new"` 前缀式。原判据只认 `"rel"` 前缀 → **F10 阶段所有 relation 硬边被误判成 topic 弱边（R=0.5），系统性降权一半**。这个 bug 比 conflict 单点更广（影响所有 F10 relation 边）。

> 只修层 1 不够：conflict 豁免 prune 进 F20 后仍被层 2 打成 R=0.5（w=0.49 而非 0.98）。两层必须同修。

## 三、修复内容（2 文件 2 处）

### 改动 1：`eval/experiment/future_sim_minloop.py:160-166`
```python
# 裁剪: 低权丢弃 + 去重 + 取 K 条最高权
# 豁免: relation 显式硬边(new/conflict/augment/equivalent 等)永不因低权被裁——
#   conflict 边 δ=-0.8 → (1-0.8)^β 在 baseline 下恒 0.20 < prune_w=0.3, 若一并裁掉
#   会让"矛盾/反向分支"这一明确定义的发散方向数学上永远出不来(结构性缺陷)。
#   硬边是强语义信号, 其价值不由 δ 权重门槛决定; 只有 topic 弱边受 prune_w 约束。
branches = [b for b in branches
            if b["rel"] != "topic_sibling" or b["weight"] >= CONFIG["branch_prune_w"]]
```

### 改动 2：`eval/experiment/f20_weight.py:112-121`
```python
def factor_edge(etype):
    """R(edge): 边类型乘子。relation 显式硬边=1.0, topic 弱边=0.5。

    兼容两种 rel 编码: F10 分支产裸 'new'/'conflict'/'augment'/'equivalent' 等,
    F30 内部产 'rel:new'/'rel:back' 前缀式。原判据只认 'rel' 前缀, 导致 F10 阶段的
    relation 硬边被误判成 topic 弱边(R 0.5), 系统性降权一半——这是编码不一致 bug。
    修正判据: 以 'topic' 开头或空/None → 弱边; 其余(rel: 前缀 或 裸 relation 词) → 硬边。"""
    e = etype or ""
    if e.startswith("topic") or not e:
        return EDGE_W["topic"]
    return EDGE_W["rel"]
```
