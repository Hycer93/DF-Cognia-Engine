## 2. 为什么拆开（四条理由）

1. **能力偏向不同**：档案库要的是检索精度与幂等（工程活），主思维要的是推理（模型活），管理员要的是稳定批处理（小模型活）——一个尺寸装不下三种活。
2. **权限隔离（保命级）**：执行端跑飞不污染记忆库。管理员只写 governor_pending.jsonl 提案队列，主库落库权在人/上位模型——两步链设计。终端执行位同样只读+提案，无直接写权。
3. **算力经济性**：记忆治理是夜间批量活，用 flash 级模型够；不必为管理员位常驻烧主模型。夜间短跑模式天然规避 CLI 内网认证过期、会话漂移。
4. **与普通 Agent 的差别**：普通 Agent 是"一个模型+工具循环"，无持久记忆主体身份；本架构是记忆库（资产）+ 管理员（守护进程）+ 主思维（决策）+ 闸门（人）四权分立——每个角色有自己的权限边界和验收通道。

## 3. 权限边界（CLI 管理员已参数级落实）

```
codechat --permission-mode bypassPermissions   # 容器内自动操作
         --no-mcp                              # 砍 trinity/jira 等生产工具
         --cwd <引擎目录>                       # 圈定工作范围
         --max-budget-usd 1.0                   # 成本上限
         --chat-id mem-governor                 # 固定会话（历史可追溯）
```

降级保护：CLI 不在线 → 记日志跳过，不崩不污染主库。

## 4. 两个补强点 ⚠（措辞待校）

1. **管理员质量的实证**：mem_governor 首跑 182s，4 条 hold 全维持 + 独立发现"引用性提及假阳性源"（后固化为 classify_topic 过滤规则，E7 裁决落地）+ 新锚种子观察，守住"禁当场二选一"和"不批量扩容"规约——8B 级小模型在受限提示词下能胜任夜间治理位，这是该架构位的首次实证。
2. **管理员产出的工程杠杆**：管理员发现的模式可回流为在线路径的硬规则（引用过滤即例证）——夜间洞察 → 在线拦截的转化通道，使管理员位不只是一个看门人，而是体系免疫系统的模式发现器。
