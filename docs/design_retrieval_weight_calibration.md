## 1. 现状盘点（先弄清"哪些已标定、哪些仍是先验"）

### 1.1 打分公式（`memory_query.py` 两段式）

```
match_eff = code_eff * W_CODE_MATCH(0.30)
          + sem        * 0.30        # 语义分（硬编码 0.30）
          + kw         * 0.30        # 关键词分（硬编码 0.30）
          + topic_boost (0.10, 命中主题内原子时)

bias_eff  = conf   * W_CONFIDENCE(0.25)
          + cited  * W_CITED_STATS(0.25)
          + rel    * W_RELATION_ACTIVATE(0.20)

total     = (match_eff + bias_eff) * t_score   # t_score 时间窗得分
```

排序不是按 total，而是两段式：
- 段1 资格池：`match_eff >= GATE_HARD_PASS(0.22)`，上限 `QUALIFIED_POOL_CAP=20`
- 段2 池内排序：`-(match_eff + min(bias_eff, BIAS_CAP=0.30))`

### 1.2 常量标定状态（`constants.py` 已标注的置信来源）

| 常量 | 当前值 | 标注状态 | 说明 |
|---|---|---|---|
| `W_CODE_MATCH` | 0.30 | `[实测带]` 0.28-0.35 中值 | 有区间但未见完整对照报告 |
| `sem` 系数 | 0.30 | **硬编码** | 未抽成常量，无标定标注 |
| `kw` 系数 | 0.30 | **硬编码** | 未抽成常量，无标定标注 |
| `W_CONFIDENCE` | 0.25 | `[先验-可校准]` | 未标定 |
| `W_CITED_STATS` | 0.25 | `[先验-可校准]` | 未标定 |
| `W_RELATION_ACTIVATE` | 0.20 | `[先验-可校准]` | 未标定 |
| `GATE_HARD_PASS` | 0.22 | `[实测标定]` | ✅ E2 扫描 F1 最优点（recall 83.6% / fp 0% / f1 0.911） |
| `GATE_HARD_ASK` | 0.12 | `[实测标定]` | ✅ E2 正例尾部上界 |
| `BIAS_CAP` | 0.30 | `[先验-可校准]` | E8 实证需要封顶但具体值未扫 |
| `TOPIC_ROUTE_BOOST` | 0.10 | `[先验]` | 未标定 |

**结论**：只有门控阈值（`GATE_HARD_PASS/HARD_ASK`）有系统标定；
匹配/偏置的**权重分配**（尤其 sem/kw 硬编码 0.30、bias 三项）仍是先验值，
`sem` 与 `kw` 甚至没有独立常量名，难以做单因素消融。

### 1.3 关键词分现状（可迭代的两个短板）

读 `memory_query.py` 的 `_kw_score`（L267-310 附近）：
- **无 IDF**：`g2 = solid / len(qgrams)`，每个 gram 等权。高频通用词（"系统/问题"）与
  稀有实体词（"3090/CIPP"）贡献相同 → 召回被泛词稀释。
- **无词序**：以 gram 集合交集计分，`"AB BA"` 与 `"BA AB"` 不可区分 → 无法利用短语顺序。
- 已有改进（保留）：碎片过滤（孤立单 gram 丢弃）、框架 gram 隔离（fw 不混入主池）。

## 2. 实验设计（对照矩阵）

> 原则：**单因素对照 + 固定评测集 + 可复现脚本**。每次只动一个变量，
> 其余冻结；所有结论须附 recall/fp/F1 或 NDCG，不给"感觉更好"。

### 2.1 评测集（先固化，否则一切对照无意义）

复用并扩充 `eval/core/e2_gate_calibration.py` 的正负组：
- **正组**：现有 61 条真记忆 + 人工语义变体（每条 ≥2 变体）
- **负组**：无主语 / 跨主题 / 泛指查询（现有 + 补足到 ≥40 条）
- **排序组**（新增，用于 NDCG）：对每组正例给出"期望 top-1 命中 inst_id"，
  度量 top-1 / top-3 命中率，弥补纯阈值标定看不到"座次"的问题。

产物：`data/probe/retrieval_eval_set.jsonl`（正/负/排序三视角统一集，带标注）。

### 2.2 对照矩阵（每行一个实验）

| 编号 | 变量 | 固定 | 度量 | 达标线 |
|---|---|---|---|---|
| R1 | `sem`/`kw`/`code` 三分量权重（现 0.30×3）在单纯形上网格扫描 | 评测集、bias 冻结 | match_eff 的 F1 + top-1 命中 | 相对现值 F1 不降且 top-1 提升 ≥3pp |
| R2 | `kw` 引入 IDF 重权（`idf(g)=log(N/df(g))`，N=库里 gram 文档数） | R1 最优权重、评测集 | 同上 | F1 不降且负例 fp 不增 |
| R3 | `kw` 引入词序（连续 gram 链命中权重 ×1.2） | R2 结果 | 同上 | top-3 命中提升 |
| R4 | bias 三项（conf/cited/rel）权重在约束下扫描 | match 冻结 | 排序组 NDCG@5 | 优于现 0.25/0.25/0.20 |
| R5 | `BIAS_CAP` 扫描（0.2~0.5） | R4 权重 | 排序组 + "高 bias 抢位"误判数 | 抢位误判下降、NDCG 不掉 |

**执行顺序**：R1（先定 match 权重骨架）→ R2/R3（kw 特征增强）→ R4（bias）→ R5（封顶）。
R2/R3 依赖 R1 的最优权重，故必须串行；R1 与 R4 理论可并行（分别动 match/bias），
但为可复现建议全串行。

### 2.3 实验脚本规格（新建，不改线上）

新建 `eval/experiment/r_weight_calibration.py`，约定：
- 通过 monkey-patch `constants.W_*` / 局部覆盖 `memory_query` 的打分系数跑对照，
  **绝不写回 constants.py**；最优值只输出到 `logs/r_weight_calibration.json` + 晨报文本。
- 每次运行打印对照表（配置 / recall / fp / F1 / NDCG@5），可 diff 两两对比。
- 补 `eval/audit/retrieval_weight_regression.py`：断言"线上常量 == 文档记录的已裁决值"，
  防止标定后改常量忘记更新文档（或反之）。

### 2.4 改值的管理纪律

- 任何权重调整走**人闸**：实验脚本给推荐值 → 用户晨间裁决 → 手工改 `constants.py`
  → 更新 §1.2 状态表 + `[实测标定]` 标注 → 补回归基线。
- 脚本不得自我修改线上权重（沿用 F20 β"人闸静态参数"同一纪律）。

## 4. 已知风险与不做的事

- **不过拟合小样本**：评测集 <100 条时，网格扫描的"最优"可能不稳健；须留出交叉验证折。
- **不混算框架 gram**：kw 的 fw 隔离机制保留，IDF 只作用于实体 gram，防止框架词借 IDF 翻身。
- **不在夜间自动改权重**：夜间只跑测量不进写；改值永远人闸。
- **不引入黑盒**：IDF/词序都是可解释特征；不引入学习型 rerank（除非先有充足标注）。
