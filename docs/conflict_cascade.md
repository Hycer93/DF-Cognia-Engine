# 冲突级联判定规约（conflict_cascade.md）

状态：2026-11-12 用户终审通过（整体路线+落地顺序+边界规约）

## 优先级路线

② 占位前置检测 → ④ 同 entity 互撞折叠 → ③ 实体锚增强判定 → ① 换 BGE/新嵌入基座

前两项为低成本、无阈值漂移、不污染已标定基线的防御补丁，优先上线；实体锚是业务语义增强；换基座是重标定级大手术，不能只为冲突误报驱动。

## 级联降级规则（已落码 memory/memory_relations.py）

1. **占位阻断**：任一方 detail 判定为占位（复用质检门禁 detect_placeholder 复合判定）→ 该层相似度不计入、不触发下钻、不强行拉高整体分数，级联停在 summary 层。
2. **不 dismiss 只分流**：占位卡对不进正常冲突队列，分流到 `summary_only_suspects.jsonl`（摘要-only 可疑对）。理由：少数场景存在摘要高度相似、detail 尚未回填的真实分叉，不能一刀切丢告警。detail 回填后复审。
3. **同 entity 折叠**：双方已挂同一 entity_id（图谱末值为准）→ 不进冲突判定流水线，留审计日志 `entity_collision_skip.jsonl`。
4. **演化链例外**：evolved_into/derive 关系的卡对不同 entity，不折叠，照常走冲突判定——防演化分支后继推翻前驱时漏抓（P10→P22 口径：同本体不再互撞，演化对万一打架仍能抓出）。

## 冲突流水线前置过滤器顺序（规约）

先查 entity 归属 → 再做占位检测 → 再执行三层级联嵌入比对（summary→detail→source_ref）。

## 实体锚增强（③ 中期，未落码）

- 不是"实体相等=同一件事"做最终判据，而是路由分支：命中专利编号簇→专利谱系核查分支；命中个股标的→交易事件核查分支。
- 实体特征是裁决线索非最终判据；给冲突对打 `entity_anchor:xxx` 供人工复核与规则消费。
- 开发前置条件：②④稳定跑通、晨报误报数量下降后再开发。

## 换嵌入基座（① 后置）

- 触发指标主看：检索召回、gate 命中率、别名匹配质量；不为冲突误报启动基座迁移。
- 若换：conflict/augment/equivalent 全套阈值、CASCADE_DROP、全库向量、E8 回归集必须整套重标定。
- 级联逻辑（摘要→detail→source_ref）本身保留，仅底层向量基座更换。
